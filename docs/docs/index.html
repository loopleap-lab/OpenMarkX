Extending MarkWeightX

How to add a watermarking method, check it, and run it through the same benchmark as the built-in ones. New to MarkWeightX? Start with the three ways to run it.

Overview

A method is one Python file: a subclass of mwx.Scheme with a key, a training signal and a score. The core does the rest: it trains the signal into the model, applies the weight and text changes, calibrates the detector and builds the leaderboard. Nothing else in the toolkit changes.

Add a method in four steps

Pick a step to see what you write or run.

my_mark.py
"""my-mark: a MarkWeightX scheme in one file. Check it with `markweightx check --adapter my_mark.py`."""
import torch

import markweightx as mwx


@mwx.register_scheme
class MyMark(mwx.Scheme):
    name = "my-mark"
    imprint = mwx.Imprint.DISTILL      # DISTILL: learn target_logits into the weights; EDIT: write weights directly
    access = mwx.Access.R0             # what the detector needs besides the text: R0, R0_AUX, R1 or R2

    def __init__(self, delta: float = 2.0, **params):
        super().__init__(delta=delta, **params)
        self.delta = delta

    def setup(self, model, tokenizer, device, key=None):
        """Key: draw a secret for a new release, or read it from an existing key. Return the key material."""
        super().setup(model, tokenizer, device, key)
        key = dict(key or {})
        if "secret" not in key:
            key["secret"] = mwx.keys.new_secret()
        g = torch.Generator().manual_seed(int(key["secret"]))
        self.green = torch.rand(model.config.vocab_size, generator=g) < 0.5
        return {"secret": int(key["secret"])}

    def target_logits(self, input_ids, logits):
        """Signal: the teacher's logits for every position (here: a fixed green list, +delta)."""
        return logits + self.delta * self.green.to(logits.device, logits.dtype)

    def score(self, text):
        """Score: a statistic (higher = more marked) and the number of tokens scored. Each distinct token counts
        once: a repeated word would otherwise count many times and make the p-value too small."""
        ids = set(self.tok(text, add_special_tokens=False)["input_ids"])
        n = max(len(ids), 1)
        g = sum(bool(self.green[i]) for i in ids)
        return (g - 0.5 * n) / (0.25 * n) ** 0.5, len(ids)

    exact_null = True                  # pvalue() below is exact, so detect() uses it even after mwx.calibrate

    def pvalue(self, statistic, n_tokens):
        """Optional closed-form null: P(score >= statistic) for unmarked text. Return None to use the key's
        calibrated empirical null instead (mwx.calibrate); with exact_null = False a calibrated null takes over."""
        import math
        n = max(n_tokens, 1)
        g = round(statistic * (0.25 * n) ** 0.5 + 0.5 * n)    # green tokens: Binomial(n, 1/2) without the mark
        return sum(math.comb(n, k) for k in range(max(g, 0), n + 1)) / 2 ** n

shell
markweightx check --adapter my_mark.py
# runs C1-C10 against a tiny Llama, on CPU, in minutes
# a failed check names what to fix; fix it and run again
shell
markweightx embed --base llama-3.2-1b --watermark my_mark.py
markweightx calibrate RELEASE_DIR --trust-plugin          # freeze the null for this key
markweightx generate RELEASE_DIR --prompts prompts.jsonl --out texts.jsonl
markweightx detect texts.jsonl --key RELEASE_DIR --trust-plugin

The checks

markweightx check is what a method must pass before it joins the leaderboard. tests/broken/ holds 17 adapters with typical bugs, and each must fail.

C1declaredimprint, access and kind are declared; kind is one embed trains
C2accessdetect with a grant one level too low is refused before any model loads
C3round tripa fresh process holding only the key reproduces the scores
C4keyfresh keys give different scores; no tiny key space
C5nullclosed-form p-values are not too small on human text; marked text gets lower p
C6signaltext decoded with the signal scores clearly above plain text
C7isolationan EDIT release holds only model files, no key material
C8determinismthe same key gives the same material and scores; setup leaves the model unchanged
C9shorter textsthe null holds for 50- and 100-token texts (needs the real base; run by the experiments)
C10positionstarget_logits on a whole sequence equals it on each prefix

Scheme reference

The parts of mwx.Scheme a method sets or overrides. The full list is in markweightx/schemes/base.py; the built-in methods in markweightx/schemes/ are working examples.

nameattributethe registry name, used by --watermark
imprintattributeDISTILL: learn target_logits into the weights; EDIT: write the weights directly
accessattributewhat the detector needs besides the text: R0, R0_AUX, R1 (base model) or R2
kindattributedistill_logit, distill_sampling or none
exact_nullattributeTrue when pvalue() is exact, so it is used even after calibrate
setup(model, tokenizer, device, key)methoddraw a new key or bind an existing one; return the key material
target_logits(input_ids, logits)methodthe teacher's logits at every position: the training signal
score(text)method(statistic, n_tokens); higher means more evidence of the mark
pvalue(statistic, n_tokens)methodoptional closed-form p-value; None uses the calibrated null
save(key_dir, key)methodwrite key files (e.g. a trained model) into the private key directory
trainable_params()methodextra parameters trained with the model, as PRO's policy
imprint_edit(model, tokenizer, out)methodEDIT methods only: write the mark into the weights

Rules for plugin files

  • One file. The key stores that file, so it cannot import a sibling module.
  • Pinned code. The key records the file's content hash; a detector scores with exactly that code, and an edited file is refused.
  • Unique names. A plugin cannot reuse a built-in method's name.
  • Trust. Plugin code named by a key runs only if your process imported that file, or with --trust-plugin (trust_plugin=True).
  • Key files go through save(key_dir, key). They land in the private key store, never in the release.
